# Phase 1 — UI Design Contract

> Visual and interaction contract for **Foundation** auth + session shell only. Generated by gsd-ui-researcher. Identity preservation wins — wire real Supabase auth; do not redesign dashboard, input zone, quiz, or flashcard surfaces.

**Impeccable register:** `product` (instrument-like study workbench; calm, precise, earned familiarity).

---

## Phase Scope

| In scope | Out of scope |
|----------|--------------|
| Login (`/login`) — wire to Supabase, preserve layout | Dashboard redesign |
| Signup (`/signup`) — wire to Supabase, preserve layout | Input zone UI |
| Logout — restore route + shell menu wiring | Quiz / flashcard UI changes |
| Protected `(app)` routes — redirect unauthenticated users | OAuth / social login |
| Auth error, loading, and redirect-after-login states | Parse / generation progress UI |
| App shell session awareness (top bar avatar, logout) | Empty states for study sets (Phase 2+) |

**Upstream decisions used:** D-12–D-15 (`01-CONTEXT.md`), CORE-AUTH-01/02 (`.planning/REQUIREMENTS.md`), brand personality (`PRODUCT.md`, `DESIGN.md`).

## Typography

**Contract limit:** 4 sizes, 2 weights (checker-compliant). Preserve existing component classes where they already match; do not add new size steps.

| Role | Size | Weight | Line Height | Class / utility |
|------|------|--------|-------------|-----------------|
| Body | 14px (`text-sm`) | 400 | 1.625 | default Manrope |
| Label | 12px (`text-xs`) | 800 | 1.2 | `font-label` uppercase, `tracking-wide` |
| Heading | 24px (`text-2xl`) | 800 (`font-extrabold`) | 1.15 | `font-heading tracking-tight` — auth card H1 |
| Display | 30px (`text-3xl`) | 800 | 1.15 | Auth aside only (`AuthBrandAside`) — max one per viewport |

**Weights:** 400 (body) and 800 (label, heading, display) only.

**Letter-spacing floor:** ≥ −0.04em on display headings (`tracking-tight` on auth H1 is compliant).

## Color

60 / 30 / 10 split on auth and shell surfaces (light mode primary target):

| Role | Token / hex | Usage |
|------|-------------|-------|
| Dominant (60%) | `--background` `#f7faf8` (Mint Paper) | Page bg, auth shell outer, app `main` bg |
| Secondary (30%) | `--card` `#ffffff`, `--muted` `#f1f4f2`, `--secondary` `#ebefed` | Auth form card, input wells, aside `bg-muted/40`, top bar `bg-card/85` |
| Accent (10%) | `--primary` `#5f0f00` (Oxblood), `--ring` `#ff967d` (Coral) | See reserved list below |
| Destructive | `--destructive` `#ba1a1a` | Auth inline errors only |

**Accent reserved for:**
- Primary submit buttons (oxblood fill)
- Focus rings on inputs and interactive controls (coral `--ring`)
- Inline auth links (`text-primary` — "Create one", "Sign in")
- Brand mark fill (`D2` square in header/aside)
- Avatar gradient endpoint (`from-(--d2q-blue)` in top bar — existing; do not change)

**Not accent in Phase 1:** page backgrounds, card fills, error text (use destructive), decorative gradients, new badges.

**Dark mode:** Existing `:root` / `.dark` tokens in `globals.css` — preserve ThemeProvider behavior; auth and shell must remain WCAG AA in both themes.

## Screens & Flows

### 1. Login (`/login`)

**Focal point:** Primary oxblood `Sign in` CTA centered in the auth card — single dominant action per viewport.

**Layout:** `AuthShell` → centered card (`max-w-[420px]`, `rounded-sm`, auth panel shadow). Preserve `LoginClient.tsx` structure.

**Fields:** Email (`type="email"`, `autoComplete="email"`), Password (`autoComplete="current-password"`). Labels: `Email`, `Password` — `font-label text-xs font-semibold uppercase`.

**Input styling (preserve):**
```
rounded-sm border-0 border-b-2 border-transparent bg-input shadow-none ring-0
focus-visible:border-primary focus-visible:ring-0
```

**States:**

| State | Visual | Behavior |
|-------|--------|----------|
| Default | Form enabled | — |
| Submitting | CTA `Signing in…`, `disabled={busy}` | `setBusy(true)` until request completes |
| Error | `text-sm text-destructive`, `role="alert"` below fields | Show `signInError.message` or generic fallback |
| Already authenticated | No loading skeleton | `router.replace(nextPath)` where `nextPath` defaults `/dashboard`, sanitized from `?next=` |
| Success | — | `router.replace(nextPath)` + `router.refresh()` |

**`?next=` contract:** Only same-origin relative paths (`startsWith("/")`, not `//`). Invalid → `/dashboard`.

### 2. Signup (`/signup`)

**Focal point:** Primary oxblood `Create account` CTA centered in the auth card.

Same layout and input styling as login.

**States:** Mirror login; success redirects to `/dashboard` (no `?next` on signup — existing behavior).

**Post-signup:** If `data.session` exists → dashboard. Else attempt `signInWithPassword`; on failure show configured error message (preserve existing copy).

### 3. Logout

**Restore** `GET /logout` route handler (or equivalent) that:
1. Calls `supabase.auth.signOut()` server-side
2. Redirects to `/login`

**App shell:** `AppTopBar` "Log out" menu item must **not** only `router.replace("/login")`. Wire to `/logout` (navigation or `fetch` + redirect) so session cookies clear.

**Loading during logout:** Disable menu item or show brief busy state optional; if omitted, full-page navigation to `/logout` is acceptable.

### 4. Protected app shell (`(app)/*`)

**Server guard:** `(app)/layout.tsx` calls `requireUser()` before rendering children. Unauthenticated → redirect `/login?next={currentPath}`.

**No intermediate "please log in" page** inside the app shell — redirect is the UX.

**Authenticated shell:** Unchanged visually — `AppShell` + `AppTopBar` + `d2q-technical-grid` on `main`. Avatar control: `aria-label="Account menu"` on the trigger (or visible account label if email is shown).

**Session refresh:** `proxy.ts` middleware refreshes Supabase session on navigation (no UI change; prevents silent auth loss).

## Accessibility

- **WCAG 2.1 AA:** `text-muted-foreground` (`#404945`) on mint paper; error text uses `text-destructive` with message text (not color alone).
- **Labels:** Every input has associated `<label htmlFor="...">`.
- **Errors:** `role="alert"` on error paragraph (existing).
- **Keyboard:** Tab order email → password → submit → cross-link. Enter submits form.
- **Focus:** Visible focus on inputs (bottom border) and buttons (ring). Preserve `focus-visible:ring-2` on shell links.
- **Reduced motion:** No new animations in Phase 1. Existing `d2q-route-transition` on app routes unchanged.
- **Landmarks:** Auth — `AuthMobileHeader` `role` implicit `<header>`; form is plain `<form>`. App — `AppTopBar` `role="banner"`, `main` landmark (existing).
