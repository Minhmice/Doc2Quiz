# Phase 2 — UI Design Contract

> Visual and interaction contract for **Input & MarkItDown** — unified input zone, validation errors, and real ingest progress. Generated by gsd-ui-researcher. Identity preservation wins — extend existing import shell; do not redesign dashboard, quiz play, or flashcard session surfaces.

**Impeccable register:** `product` (instrument-like study workbench; calm, precise; no PDF-centric copy, no AI-slop landing grammar).

- Progress status card left accent stripe: **6px** (`border-l-[6px]`) — existing `NewStudySetPdfImportProgressChrome` signature; preserve.

## Typography

**Contract limit:** 4 sizes, 2 weights (checker-compliant).

| Role | Size | Weight | Line Height | Class / utility |
|------|------|--------|-------------|-----------------|
| Body | 14px (`text-sm`) | 400 | 1.625 | Default Manrope — subcopy, hints, errors |
| Label | 12px (`text-xs`) | 800 | 1.2 | `font-label` uppercase, `tracking-wide` — tab strip, progress eyebrow, field labels |
| Heading | 24px (`text-2xl`) | 800 | 1.25 | Page section titles inside cards (if needed) |
| Display | 30px (`text-3xl`) | 800 | 1.15 | Page H1 only (`font-display` / `tracking-tight`) — one per viewport |

**Weights:** 400 (body) and 800 (label, heading, display) only. Existing `font-semibold` (600) on H1 in `NewStudySetTextImportFlow` → normalize to **800** during refactor.

**Monospace:** Paste textarea body may use `font-mono text-sm` for source text only — not a fifth size tier (still 14px).

## Color

60 / 30 / 10 split on import workbench surfaces (light mode primary target):

| Role | Token / hex | Usage |
|------|-------------|-------|
| Dominant (60%) | `--background` `#f7faf8` (Mint Paper) | Workbench `main`, page canvas |
| Secondary (30%) | `--card` `#ffffff`, `--muted` `#f1f4f2`, `bg-card/60` | Input card shell, tab list `bg-muted`, drop zone idle fill |
| Accent (10%) | `--primary` `#5f0f00` (Oxblood), `--ring` `#ff967d` (Coral), `--chart-2` `#376757` (Forest Sage) | See reserved list |
| Destructive | `--destructive` `#ba1a1a` | Validation errors, failed ingest |

**Accent reserved for:**
- Primary CTA button fill (oxblood)
- Focus rings on inputs, tabs, drop zone (`ring-ring/50` coral)
- Active ingest progress stripe (`border-d2q-accent` / coral left bar on status card)
- Back navigation link text (`text-chart-2` forest sage — existing quiz/flashcards pages)
- Drop zone drag-active border emphasis (`--d2q-border-strong` / primary tint)
- Active tab indicator underline (`bg-primary` on `ImportStepTabStrip`)

**Not accent:** page backgrounds, card fills, body copy, error text (use destructive), decorative gradients, uppercase eyebrows on every block.

**Drop zone idle:** dashed `border-border/60`, background `bg-muted/30` at rest; drag-active `bg-accent/10` wash — preserve `UploadBox` motion vocabulary.

### Import step tab strip (`ImportStepTabStrip`)

Update `PHASE_LABELS` — format-agnostic, pipeline-aligned:

| Step key | Label |
|----------|-------|
| `upload` | `Add source` |
| `read` | `Convert` |
| `generate` | `Review` |

### Ingest progress (real steps only — D-12)

Display **one active label** at a time in the status card headline. No percentage bar. Optional indeterminate stripe animation on the active step row only (`d2q-progress-stripes`).

| Step | Eyebrow (`font-label`) | Headline |
|------|------------------------|----------|
| `validating` | `Step 1 of 3` | `Validating input…` |
| `uploading` | `Step 2 of 3` | `Uploading file…` |
| `converting` | `Step 3 of 3` | `Converting to Markdown…` |
| `done` | — | (navigate away; no persistent card) |
| `error` | `Conversion failed` | Server message or fallback below |

**Paste / YouTube paths:** Skip `uploading` visually — advance `validating` → `converting` (still 3-step strip shows step 2 as completed or hidden; executor may collapse to 2 user-visible steps for non-file inputs).

### Empty states

| Context | Heading | Body |
|---------|---------|------|
| File tab (no file) | — | Drop zone copy above (not a separate empty card) |
| Paste tab (no text) | — | Placeholder only; CTA disabled |
| YouTube tab (empty URL) | — | Placeholder only; CTA disabled |

### Error states

| Scenario | Copy |
|----------|------|
| Client: no input | Toast: `Add a file, paste text, or enter a YouTube URL before continuing.` |
| Client: unsupported file type | Toast: `That file type isn't supported. Use PDF, Office, images, audio, HTML, CSV, JSON, XML, or plain text.` |
| Client: file too large | Toast: `{filename} is too large. Maximum size for this type is {limit}.` |
| Client: invalid YouTube URL | Toast: `Enter a valid YouTube URL (youtube.com or youtu.be).` |
| Client: paste too short | Toast: `Paste at least a few lines of text before continuing.` |
| Server 4xx (validation) | Toast or inline alert: use API `message` verbatim when present; fallback `We couldn't accept that input. Check the file type and size, then try again.` |
| Server 5xx / conversion failure | Toast: API `message` or `Conversion failed. Try a different file or paste the text directly.` |
| Network error | Toast: `Connection lost. Check your network and try again.` |

### Destructive confirmation

None in Phase 2 — no delete/cancel-ingest requirement. User may navigate away via Back link (browser handles in-flight request; no confirmation dialog).

## Unified Input Zone — Interaction Spec

### Tab behavior

- Default tab: **File**
- Tabs are **not** persisted across navigation (remount = File)
- Switching tabs does **not** clear other tab's draft unless user submits
- `role="tablist"` / `role="tabpanel"` via shadcn Tabs

### File panel

- Reuse `UploadBox` **tall** mode: full-width dashed drop target, `CloudUpload` icon, breathe animation when `prefers-reduced-motion: no`
- `accept` attribute: all extensions matching `SUPPORTED_MIME_TYPES` from `validation.ts`
- Client validation via shared `validation.ts` helpers before POST
- On valid pick: show filename + size below zone (preserve `pickedMeta` pattern)
- Drag-and-drop + hidden `<input type="file">` + keyboard activation on "Choose file" span

### Paste panel

- `Textarea` `min-h-[280px] resize-y font-mono text-sm`
- Label: `Source text` with `font-label` styling (match existing text flow)
- No separate ".txt upload" button in Phase 2 — file types cover plain text; optional `.txt` via File tab

### YouTube panel

- Single-line `Input` `type="url"` with `autoComplete="off"`
- Client pattern: `youtube.com` or `youtu.be` host check before submit

### Primary CTA placement

- Bottom of card, right-aligned on `sm+`, full-width on mobile
- `disabled` when active tab has no valid input or `busy`
- Only one CTA for all tabs — label always `Convert document`

## Ingest Progress — Interaction Spec

### State machine (UI)

```
idle → validating → uploading? → converting → redirect
                  ↘ error (toast + return to idle)
```

| UI `ingestStep` | `StudySetNewImportStep` | Visible UI |
|-----------------|-------------------------|------------|
| `idle` | `upload` | UnifiedInputZone |
| `validating` | `read` | IngestProgressCard |
| `uploading` | `read` | IngestProgressCard (file only) |
| `converting` | `read` | IngestProgressCard |
| `done` | `generate` | Brief flash then `router.push(postIngestHref)` |
| `error` | `upload` | Hide progress card, restore input zone, toast error |

### IngestProgressCard layout

Adapt v1 progress chrome **without** green banner strip or AI parse panel:

```
┌──────────────────────────────────────────────────┐
│ font-label eyebrow (Step N of 3)                 │
│ Headline (Validating input…)                     │
│ ┌──────────────────────────────────────────────┐ │
│ │ Step list: Validating | Uploading | Converting│ │
│ │ (check / spinner / muted for each)           │ │
│ └──────────────────────────────────────────────┘ │
│ ▼ Technical details (collapsed)                  │
└──────────────────────────────────────────────────┘
```

- Card: `rounded-xl ring-1 ring-foreground/10 bg-card`
- Top region: `border-l-[6px] border-d2q-accent` accent on status block (preserve signature)
- **No** `importUiProgressPercent` fake 33/66/100 bar — use step checklist + optional indeterminate stripe on active row only
- `aria-live="polite"` on headline element for screen readers
- `ImportFlowTechnicalDetails` lines: MIME, filename, ingest step, API error code

## Accessibility

- **WCAG 2.1 AA:** Muted hint text uses `text-muted-foreground`; errors use `text-destructive` + message text.
- **Tabs:** Arrow keys navigate tab list; `aria-selected` on active tab.
- **Drop zone:** `role="button"` or native file input labeled; instructions not color-only.
- **Progress:** `aria-live="polite"` region updates on step change; step list uses text labels (not hue alone).
- **Keyboard:** Tab order: Back → step strip → input tabs → panel fields → CTA.
- **Touch targets:** CTA and tab triggers ≥ 32px height (existing button default).
