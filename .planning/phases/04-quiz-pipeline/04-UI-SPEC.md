# Phase 4 — UI Design Contract

> Visual and interaction contract for **Quiz pipeline** — mode selection on canonical preview, quiz generation progress, review/edit wiring, practice session, done summary, and dashboard re-entry. Generated by gsd-ui-researcher. **Extend Phase 3** — do not redesign dashboard shell, import flows, or quiz-play stitch theme.

**Impeccable register:** `product` (instrument-like study workbench; calm, precise; document-first ledger aesthetic).

---

| In scope | Out of scope |
|----------|--------------|
| Mode selection on `/sets/[id]/source` — Quiz + Flashcards CTAs | Flashcard generation UI (Phase 5) |

## Mode Selection — Interaction Spec

### Visibility

- Show when `pipeline_stage ≥ canonical` and UI is in `preview` state.
- Hide when `generating` or `canonicalizing` (Phase 3).
- When `pipeline_stage === 'quiz'` with `approvedCount > 0`, replace with resume strip (see above).

### Quiz path (D-01, D-02)

1. User clicks **Quiz**.
2. Client PATCH/POST sets `content_kind = 'quiz'`, `pipeline_stage = 'mode_selected'` (optimistic OK; server is source of truth).
3. Immediately transition to `generating`; `POST /api/study-sets/[id]/quiz/generate` with optional `{ questionCount }` if user override UI is exposed later (Phase 4: **no count override control** — use server recommendation only; defer override input).
4. On 2xx: read `{ recommendedCount, generatedCount, questionIds }`; show success line 1.5s or immediate redirect to `/edit/quiz/[id]`.
5. On error: show `QuizGenerateProgressCard` error state + **Try again**.

### Flashcards path (Phase 5 stub)

- Button `disabled`, `aria-disabled="true"`.
- Optional: `onClick` on wrapper prevented; `toast.info('Flashcards are coming soon.')` if executor wants click feedback — prefer no toast on disabled control.
- Do not route anywhere.
